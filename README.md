# ESP32 Hub Board

برد ارتباطی هاب: وب‌سرور آفلاین + وای‌فای + پل UART به STM32 + کنسول مودم GSM.

## ساختار کد (عمداً ساده)

```
src/
├── config.h        همه ثابت‌ها: پین‌ها، نام AP، تایم‌اوت‌ها، جدول پروتکل
├── hub.h/.cpp      ⭐ تنها جای «متغیرها» — یک struct شامل تمام تنظیمات و وضعیت‌ها
│                   + توابع apply_* (اعمال تغییر) + hub_to_json (خروجی وب)
├── store.h/.cpp    ذخیره وای‌فای و سرور در NVS (بعد از ریست می‌ماند)
├── uart_link.h/.cpp پروتکل UART با STM32: پارس SET/STATE/REQ/GSM + ارسال
├── net.h/.cpp      وای‌فای غیرمسدودی: اتصال state-machine + اسکن async
│                   + تشخیص «رمز اشتباه/تایم‌اوت» + پینگ سرور در تسک جدا
├── gsm_log.h/.cpp  بافر حلقه‌ای لاگ‌های مودم GSM برای کنسول وب/سریال
├── shell.h/.cpp    شل سریال USB: state/wifi/server + همه فرمان‌های GSM
├── web_api.h/.cpp  ⭐ کل API فقط ۱۰ مسیر (پایین را ببین)
├── main.cpp        setup/loop — فقط سیم‌کشی ماژول‌ها به هم (~۲۵ خط)
├── index_html.h    تولید خودکار از web/index.html (دست نزن)
└── web/index.html  پنل وب آفلاین (فارسی RTL، بدون هیچ CDN/فونت خارجی)
tools/
└── html2header.py  بعد از هر تغییر index.html:  python tools/html2header.py
```

**قانون طلایی:** هر متغیر جدید → فقط `hub.h`. هر API جدید → فقط یک تابع در `web_api.cpp`. هر پیام پروتکل جدید → فقط یک شاخه در `uart_link.cpp`.

## API (کامل و همه‌اش همین است)

| متد | مسیر | بدنه/خروجی |
|---|---|---|
| GET | `/` | پنل وب |
| GET | `/api/state` | **همه‌چیز**: تنظیمات + وضعیت زنده + وضعیت GSM (`wifi.phase/err` + `gsm.*`) |
| GET | `/api/scan` | `{"scanning":b,"networks":[...]}` اسکن async — صدا بزن تا تموم شود |
| GET | `/api/ping` | `{"ok":true/false}` تست سرور مرکزی |
| GET | `/api/gsm?after=N` | لاگ‌های کنسول مودم بعد از شماره N |
| POST | `/api/wifi` | `{"ssid","pass"}` → ذخیره NVS + اتصال + اطلاع به STM32 |
| POST | `/api/server` | `{"domain","rate"}` → ذخیره NVS + اطلاع به STM32 |
| POST | `/api/sim` | `{"p1","p2","p3","mask"}` → ارسال به STM32 (در EEPROM ذخیره می‌شود) |
| POST | `/api/device` | `{"id","sp_t","sp_h","mask","paired"}` → ارسال به STM32 |
| POST | `/api/gsm` | `{"cmd":"sms 0912... hi"}` → اجرای فرمان روی مودم دستگاه |

پاسخ همه POST ها: `{"ok":true}` یا `{"ok":false}`

## وضعیت اتصال وای‌فای (برای پیام خطا)

`/api/state` → `wifi.phase` / `wifi.err`:

| phase | معنی |
|---|---|
| 0 | بی‌کار / ذخیره شده ولی وصل نیست |
| 1 | در حال اتصال |
| 2 | متصل |
| 3 | اتصال ناموفق → به `err` نگاه کن: `1` رمز اشتباه، `2` شبکه پیدا نشد/تایم‌اوت، `3` خطای دیگر |

## شل سریال ESP32 (کابل USB)

در Serial Monitor (115200) بنویس:

```
help                 لیست فرمان‌ها
state                خروجی JSON کامل
wifi <ssid> <pass>   ذخیره + اتصال وای‌فای
server <domain>      ذخیره آدرس سرور
sms 09121110000 hi   ← بقیه مستقیم به CLI مودم دستگاه می‌روند:
dial 09121110000       i s r d b p x h R K L T C m q
ussd *140#             at AT+CSQ
```

لاگ‌های مودم هم به‌صورت زنده با پیشوند `[GSM]` در همین سریال چاپ می‌شوند.

## ساخت و فلش

```bash
pio run -t upload && pio device monitor
```

وابستگی خارجی فقط یکی است: `ArduinoJson` (در platformio.ini هست، خودکار نصب می‌شود).

## چرخه روشن شدن (بوت)

1. `store_load()` → وای‌فای و سرور از NVS خوانده می‌شود
2. اکسس‌پوینت `ESP32_HUB_AP / 12345678` همیشه روشن (پنل آفلاین همیشه در دسترس: `192.168.4.1`)
3. اگر وای‌فای ذخیره شده و `auto=1` → اتصال نام‌هنگام شروع می‌شود
4. وب‌سرور روی پورت ۸۰ بالا می‌آید + تسک پینگ سرور استارت می‌شود
5. در حلقه: وب + UART + مدیریت اتصال + شل سریال (هیچ‌کدام بلاک نمی‌شوند)
6. اگر STM32 متصل باشد، ظرف حداکثر ۱۰ ثانیه کل تنظیمات و وضعیت‌ها را دریافت می‌کنی

## رفتارهای مهم

- **هیچ مسیر بلاک‌کننده‌ای وجود ندارد:** اسکن وای‌فای async است، پینگ سرور در تسک جدا اجرا می‌شود، اتصال وای‌فای state-machine است — وب و UART هیچ‌وقت فریز نمی‌شوند. (قبلاً `WiFi.scanNetworks()` همگانی ۲-۴ ثانیه کل برد را قفل می‌کرد.)
- **ذخیره‌سازی هوشمند:** `apply_wifi` / `apply_server` / `apply_sim` فقط وقتی مقدار واقعاً عوض شده `true` برمی‌گردانند؛ سینک تکراری STM32 باعث فرسودگی فلش نمی‌شود.
- **تشخیص قطعی STM32:** اگر ۱۵ ثانیه پیغامی نرسد، چیپ «برد اصلی» در پنل قرمز می‌شود.
- **کنسول GSM:** مودم روی برد اصلی است؛ فرمان‌ها با `GSM:CMD` می‌روند، لاگ/نتیجه/وضعیت زنده با `GSM:LOG` و `GSM:ST` برمی‌گردند و هم در تب GSM وب و هم در سریال USB دیده می‌شوند.
- **سازگاری با فریمور قدیمی:** دستورهای قدیمی `WIFI:SCAN`، `WIFI:CONNECT:ssid:pass`، `SERVER:PING:domain` هم قبول می‌شوند.

## محدودیت

- در SSID/رمز/دامنه/متن فرمان‌ها کاراکتر `|` استفاده نکن (جداکننده پروتکل است) — عملاً هیچ شبکه‌ای چنین اسمی ندارد.
