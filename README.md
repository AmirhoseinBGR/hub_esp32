# ESP32 Hub Board

برد ارتباطی هاب: وب‌سرور آفلاین + وای‌فای + پل UART به STM32.

## ساختار کد (عمداً ساده)

```
src/
├── config.h        همه ثابت‌ها: پین‌ها، نام AP، تایم‌اوت‌ها، جدول پروتکل
├── hub.h/.cpp      ⭐ تنها جای «متغیرها» — یک struct شامل تمام تنظیمات و وضعیت‌ها
│                   + توابع apply_* (اعمال تغییر) + hub_to_json (خروجی وب)
├── store.h/.cpp    ذخیره وای‌فای و سرور در NVS (بعد از ریست می‌ماند)
├── uart_link.h/.cpp پروتکل UART با STM32: پارس SET/STATE/REQ + ارسال
├── net.h/.cpp      مدیریت وای‌فای (اتصال غیرمسدودی + تلاش مجدد) + پینگ سرور
├── web_api.h/.cpp  ⭐ کل API فقط ۷ مسیر (پایین را ببین)
├── main.cpp        setup/loop — فقط سیم‌کشی ماژول‌ها به هم (~۲۰ خط)
├── index_html.h    تولید خودکار از web/index.html (دست نزن)
└── web/index.html  پنل وب آفلاین (فارسی RTL، بدون هیچ CDN/فونت خارجی)
tools/
└── html2header.py  بعد از هر تغییر index.html:  python tools/html2header.py
```

**قانون طلایی:** هر متغیر جدید → فقط `hub.h`. هر API جدید → فقط یک تابع در `web_api.cpp`. هر پیام پروتکل جدید → فقط یک شاخه در `uart_link.cpp`.

## API (کامل و همه‌اش همین است)

| متد | مسیر | بدنه/خروجی |
|---|---|---|
| GET | `/` | پنل وب |
| GET | `/api/state` | **همه‌چیز**: تنظیمات + وضعیت زنده (وب هر ۲ ثانیه می‌خواند) |
| GET | `/api/scan` | `{"networks":[...]}` اسکن وای‌فای |
| GET | `/api/ping` | `{"ok":true/false}` تست سرور مرکزی |
| POST | `/api/wifi` | `{"ssid","pass"}` → ذخیره NVS + اتصال + اطلاع به STM32 |
| POST | `/api/server` | `{"domain","rate"}` → ذخیره NVS + اطلاع به STM32 |
| POST | `/api/sim` | `{"p1","p2","p3","mask"}` → ارسال به STM32 |
| POST | `/api/device` | `{"id","sp_t","sp_h","mask","paired"}` → ارسال به STM32 |

پاسخ همه POST ها: `{"ok":true}` یا `{"ok":false}`

## ساخت و فلش

```bash
pio run -t upload && pio device monitor
```

وابستگی خارجی فقط یکی است: `ArduinoJson` (در platformio.ini هست، خودکار نصب می‌شود).

## چرخه روشن شدن (بوت)

1. `store_load()` → وای‌فای و سرور از NVS خوانده می‌شود
2. اکسس‌پوینت `ESP32_HUB_AP / 12345678` همیشه روشن (پنل آفلاین همیشه در دسترس: `192.168.4.1`)
3. اگر وای‌فای ذخیره شده و `auto=1` → اتصال نام‌هنگام شروع می‌شود
4. وب‌سرور روی پورت ۸۰ بالا می‌آید
5. در حلقه: وب + UART + مدیریت اتصال (اگر وای‌فای افتاد، هر ۲۰ ثانیه تلاش مجدد)
6. اگر STM32 متصل باشد، ظرف حداکثر ۱۰ ثانیه کل تنظیمات و وضعیت‌ها را دریافت می‌کنی

## رفتارهای مهم

- **ذخیره‌سازی هوشمند:** `apply_wifi` / `apply_server` فقط وقتی مقدار واقعاً عوض شده `true` برمی‌گردانند؛ یعنی سینک تکراری ۱۰ ثانیه‌ای STM32 باعث فرسودگی فلش نمی‌شود.
- **بدون بلوک:** اتصال وای‌فای state-machine است، `delay(8000)` قدیمی حذف شد؛ وب حین اتصال هم پاسخ می‌دهد.
- **تشخیص قطعی STM32:** اگر ۱۵ ثانیه پیغامی نرسد، چیپ «برد اصلی» در پنل قرمز می‌شود.
- **پینگ دوره‌ای سرور:** هر ۶۰ ثانیه خودکار + نتیجه به STM32 هم می‌رود (آیکون UI دستگاه تازه می‌شود).
- **سازگاری با فریمور قدیمی:** دستورهای قدیمی `WIFI:SCAN`، `WIFI:CONNECT:ssid:pass`، `SERVER:PING:domain` هم قبول می‌شوند.

## محدودیت

- در SSID/رمز/دامنه کاراکتر `|` استفاده نکن (جداکننده پروتکل است) — عملاً هیچ شبکه‌ای چنین اسمی ندارد.
